# 첫 촬영 영상 검출·설정 적용 결과

입력: `20261006_141148.mp4`와 사용자가 저장한 `calibration.json`.
1920×1080, 약 10.07초, 598프레임, 평균 약 59.43fps입니다.
영상·설정·분석 기록은 Jetson의 Git 제외 `data/video-tests/20261006-141148`와 `.runtime`에 보관했습니다.
Pi 게임·MCU에는 이 녹화 영상의 관측을 전송하지 않았습니다.

## 동일 YOLOv8n·ByteTrack 비교

| 항목 | 추론 입력 320 | 추론 입력 640 |
|---|---:|---:|
| 사람 검출 프레임 | 356 / 598 | 598 / 598 |
| 사람 미검출 프레임 | 242 | 0 |
| 영역 안 사람 검출 프레임 | 275 | 516 |
| ID 1이 부여된 프레임 | 319 | 585 |
| ID 1 최초 관측 | 약 4.69초 | 약 0.22초 |

640에서는 모든 프레임에 사람 박스 하나가 출력됐고, 초기 ID 미확정 13프레임 이후
ID 1이 끝까지 유지됐습니다. 수치는 이 영상의 관측 결과이며 일반적인 검출 정확도를 뜻하지 않습니다.
320에서는 초반 원거리 사람을 자주 놓칩니다. 이 영상 재생에는 `--imgsz 640`을 사용합니다.
기존 웹캠 기본값은 바꾸지 않았으며 실시간 속도와 카메라 구도는 별도 평가해야 합니다.

ROI는 복도 바닥, 결승선은 카메라 앞쪽, 통과 방향은 카메라 쪽으로 적용됐습니다.
추적된 박스 아래쪽 중앙이 지정 선분을 지정 방향으로 가로지르는 변화는
약 8.211~8.228초 사이에 1회 관측됐습니다. 이는 발 위치 기록을 이용한 사후 기하학 확인입니다.
참가자 등록·생존 상태·Pi 경기 단계를 검사한 게임 통과 판정은 아직 아닙니다.
영상 후반의 ROI 제외는 지정 구역에서 발 위치가 벗어난 것이며 탈락으로 처리하지 않습니다.

## 원본 해상도 변환과 전체 프레임 비교 (2026-10-06)

원본을 보존하고 `20261006_141148-960x540.mp4`, `20261006_141148-640x360.mp4`를 만들었다.
16:9 비율과 598프레임을 유지하고 영상은 H.264 CRF 20, 오디오는 원본 스트림을 복사했다.
원본은 HEVC이므로 아래 속도 개선에는 해상도와 코덱 변경이 모두 포함된다.
가변 프레임 입력을 `-vsync 0`으로 변환했다. 인코더 시간 단위 반올림으로
변환본 길이는 약 10.068초이며 원본 비디오 스트림 약 10.062초와 작은 차이가 있다.
정규화 좌표와 비율을 유지하므로 기존 calibration을 그대로 적용했다.

세 영상 모두 YOLOv8n FP32/CUDA, `imgsz=640`, `conf=0.35`, ByteTrack을 사용했다.
각 입력 크기로 준비 5프레임 처리 후 추적 상태와 영상을 초기화하고 전체 598프레임을 검사했다.
모델 준비·결과 파일 저장·화면 표시는 처리 시간에서 제외하고,
입력 읽기·검출·추적·ROI·통과 후보 계산을 포함했다. VNC 서비스는 활성 상태였고 Pi 접속은 하지 않았다.

960×540의 미검출 4프레임은 초반 약 0.153초 이내,
640×360의 미검출 18프레임은 초반 약 0.305초 이내였다.
이 결과는 해당 한 명 영상의 관측 결과이며 일반 정확도나 정지/이동 판정 검증을 뜻하지 않는다.
이 영상의 다음 개발 테스트는 960×540을 선택한다. 원본 대비 약 2.55배 빠르고,
640×360은 추가 속도 이득이 약 4%지만 원거리 검출 손실이 더 크다.
GPU 추론 시간은 거의 그대로이며 주로 원본 HEVC 읽기/디코딩 비용을 줄였다.
화면 표시를 켠 실제 VNC FPS는 위 수치와 다르다. 모든 프레임을 처리하는 현재 재생은
원본 약 59fps보다 여전히 느리며 실시간 재생에는 최신 프레임 선택 방식이 필요하다.

결과는 Jetson `.runtime/resolution-comparison/report.json`, 각 영상의 프레임 기록과 확인 이미지에 저장했다.
PC `.runtime/resolution-comparison/`에는 두 변환 영상, 보고서, 960×540 교차 확인 이미지를 복사했다.
사용한 진단 스크립트는 Jetson `.runtime/compare_resolutions.py`와 PC `.connection-setup/compare_resolutions.py`다.
VNC에는 960×540, `imgsz=640`, 화면 표시만 켜고 매 프레임 JPEG 저장을 끈 테스트를 실행했다.

변환 명령(출력별 적용):

```bash
ffmpeg -nostdin -filter_threads 1 -i 20261006_141148.mp4 \
  -map 0:v:0 -map '0:a?' -vf scale=960:540 -vsync 0 \
  -c:v libx264 -preset fast -crf 20 -pix_fmt yuv420p -threads 2 \
  -c:a copy 20261006_141148-960x540.mp4
# 640×360 변환은 scale=640:360과 출력 파일명을 변경한다.
```
