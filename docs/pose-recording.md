# 관절 시험 기록과 분석

웹의 관절 시험 데이터 기록에서 장면을 고르고 테스트 시작/중지를 누른다.
각 장면(정지, 팔 이동, 몸 회전, 거리 변화, 두 사람 교차)은 10~20초씩 별도 시험으로 기록한다.
저장 완료 표시와 시험 ID를 확인하고 다음 장면을 시작한다.
웹 미리보기5Hz가 아니라 실제 추론 완료마다 데이터를 받는다. 센서30fps 전체 원본을
기록하는 것은 아니며, 추론하지 않은 프레임에는 좌표 기록이 없다.

- 저장: Jetson repo/.runtime/pose-recordings/<시험 ID>/.
- metadata.json: 장면·모델 설정·시작 UTC·구역/결승선 설정.
- samples.jsonl: 순번, 미디어/프레임 전달/결과 완료 시각, 박스·신뢰도·ID·17개 관절,
  처리 시간/검출 간격, 기존 시험 상태·설정 버전·소스 크기·대응 JPEG 파일명.
- frames/*.jpg: 해당 추론 입력의 원본 화면(JPEG 품질85). 관절과 박스는 좌표로 재구성한다.
- summary.json: 완료/오류, 접수/저장/누락/이미지 누락, 처리 간격 요약·인원 범위.

파일은 장비 사용자만 접근하는 폴더(700)에 보관하고 완료된 파일은600 권한이다.
영상·좌표는 Git 제외다. 기록은 서버에서 유지되므로 웹 새로고침으로 중지되지 않는다.
서비스 재시작/장비 종료 시 중단될 수 있다. 재시작 후 UI에는 이전 시험 목록을 자동 표시하지 않지만
파일은 남아 있으며 시험 ID나 폴더를 통해 찾는다. 강제 전원 차단은 완성된 기록을 보장하지 않는다.

## 저장 부하와 제한

추론 스레드는 프레임 사본을 제한된 큐(16개)에 넘기고 별도 스레드가 JPEG·JSONL을 쓴다.
큐가 가득 차면 추론을 기다리게 하지 않고 그 표본을 누락으로 센다. 유효한 분석에는
누락 수·검출 간격·신뢰도와 프레임을 함께 확인해야 한다. 큐 복사와 JPEG CPU 작업의 부하는
존재하며 무기록 상태와 비교해야 한다. 기록 중 측정값을 기존 벤치마크와 섞지 않는다.

최대120초/6000표본 자동 중지, JPEG 약512MiB 제한(좌표 파일 공간 별도),
시작 시 여유1GiB 이상 필요. 중지는 즉시 접수를 막고 대기 중인 표본을 마무리한다.
저장 마무리 중에는 새 시험을 시작하지 못한다. 자동 파일 삭제는 하지 않는다.
디스크/인코딩 오류는 저장 오류로 표시하며 부분 기록이 남을 수 있다.

## 분석

중지 후 저장 완료가 표시되면 시험 ID와 실제 동작을 알려준다. 같은 순번의 프레임·좌표를
대조해 관절 흔들림/누락/ID 공백을 검토한다. 기본 수치 분석은 아래처럼 실행한다.

```bash
cd /home/jetson/projects/mugunghwa/repo
/home/jetson/yolo_v8/bin/python jetson/analyze_pose_recording.py .runtime/pose-recordings/<시험-ID>
```

analysis.json에는 관절 신뢰도 개수, ID별 관측 수/공백, 검출 간격p95,
인접 표본 관절 변화(박스 높이 단위)를 저장한다. 변화량에는 실제 움직임과 추정 오차가 함께
들어 있으므로 움직이는 시험의 큰 변화량을 흔들림/오탐이라고 단정하지 않는다.
정지 시험과 실제 JPEG를 대조해야 한다. JPEG 압축 오차가 있고 수동 정답 주석이 없으므로
이 결과를 정확도나 전체 카메라→브라우저 지연이라고 표현하지 않는다.
관절 기반 탈락 판정은 여전히 미연결이며 기존 박스 시험 상태와 구분한다.

## 자동 검증

Jetson 전체33개 테스트 통과: 기록/중지/재시작 가능한 새 시험, 프레임·JSON 대응,
표본 없는 시간 제한, 중복 시작, IO 오류, 제한 큐·누락 계수, HTTP 요청 방어/시작/중지 포함.
실제 웹 기능·저장 부하 검증 결과는 확인 뒤 갱신한다.

## 2026-10-07 실제 기능 검증

기능 확인용 빈 장면(mixed, 시험20261007T032707Z-92da0b64)에서 웹 시작/중지와
저장 완료·시작 버튼 재활성화를 확인했다. 34초 동안525표본/525JPEG,
큐 누락0·이미지 누락0, JPEG 합계27,287,974bytes(약26MiB)를 저장했다.
첫/마지막 JPEG는640×480으로 디코드되고 JSON과 이미지 개수가 일치했다.
관절 FP16/640×480 웹캠/웹 JPEG5Hz/원본 JPEG85 기록 조건에서 평균 검출 간격64.82ms,
p95 68.8ms, 평균 처리49.97ms였다. 무기록 브라우저의 최근평균 약64~65ms 표본과 큰 차이는
보이지 않았지만, 같은 시간의 엄밀한 부하 비교나 사람/다인 부하 검증은 아니다.
분석 도구 실행 성공, 사람0명525표본이라 관절 정확도·흔들림 검증에는 사용하지 않는다.
분석 회귀2개를 보강해 Jetson 전체35개 테스트 통과.
