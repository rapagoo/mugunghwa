# 무궁화 꽃이 피었습니다 — 최신 11장 공동발표 대본

홍성록: 1·2·5·6·7·9·10·11장 / 박정환: 3·4·8장 전체
배정 시간: 홍성록 약 5분, 박정환 약 4분 15초. 합계 9분 15초 + 전환 여유 약 45초 = 10분 목표(시연 영상 제외).
표시 시간은 배정값이며 실제 낭독 시간은 아직 측정하지 않았습니다. 장 제목과 대괄호 안내는 읽지 않습니다.

## 1장 — 무궁화 꽃이 피었습니다. / 홍성록 / 35초

안녕하세요. 14조 홍성록, 박정환입니다.

처음에는 수업에서 배운 내용을 활용하면서, 재미있게 해볼 수 있는 IoT 프로젝트가 없을까 고민했습니다. 그러다가 익숙한 놀이인 ‘무궁화 꽃이 피었습니다’를 직접 만들어보기로 했습니다.

인형이 뒤를 보면 움직이고, 앞을 보면 멈추는 규칙입니다.

이걸 장치가 대신하려면 누가 움직였는지 알아내야 합니다. 또 인형이 돌아보는 때에 맞춰 판단해야 합니다. 저희는 이 두 가지를 중심으로 게임을 만들었습니다.

## 2장 — 네 장치가 역할을 나눠 하나의 경기를 진행합니다 / 홍성록 / 30초

게임은 이 네 장치가 함께 진행합니다.

Jetson은 카메라 영상을 보고 사람의 움직임을 알아냅니다. Pi는 지금 움직여도 되는 때인지 확인하고, 통과와 탈락을 결정합니다.

STM32는 버튼과 인형, LED를 제어하고 LCD에 경기 현황을 보여줍니다. Arduino는 떨어진 위치에서도 현황을 볼 수 있도록 별도 LCD를 맡았습니다.

저는 Pi와 Jetson을, 박정환님은 STM32와 Arduino를 담당했습니다. 먼저 인형과 표시 장치는 박정환님이 설명드리겠습니다.

[홍성록 → 박정환 인계]

## 3장 — 버튼으로 경기를 조작하고 인형과 LCD로 진행 상황을 보여줍니다 / 박정환 / 75초

저는 STM32와 Arduino를 담당했습니다.

STM32에는 시작·정지 버튼과 모터, LED, LCD를 연결했습니다. 모터는 인형을 앞이나 뒤로 돌리는 역할입니다.

시작 버튼을 누르면 STM32가 Pi에 게임 시작을 요청합니다. Pi가 인형을 돌리라는 명령을 보내면, STM32는 Wi-Fi 모듈인 ESP-01로 받아 모터를 움직입니다. LED도 회전 상태에 맞춰 바뀝니다.

회전은 시작, 진행 중, 완료로 나눠 처리했습니다. 프로그램이 지금 어느 상태인지 짧은 간격으로 확인합니다.

설정한 회전 처리가 끝나면 Pi에 완료됐다고 알려줍니다. Pi는 이 신호를 확인하고 다음 동작을 진행합니다.

시작 전 LCD에는 GAME WAITING과 READY!가 표시됩니다. 경기 중에는 남은 시간과 전체 참가자 수, 통과·탈락 인원을 보여줍니다. 정지 버튼을 누르면 Pi에 게임 중단을 요청합니다.

이렇게 버튼으로 게임을 조작하고, 인형과 LCD로 진행 상황을 확인하도록 했습니다.

## 4장 — 떨어진 곳에서도 같은 경기의 시간과 결과를 확인합니다 / 박정환 / 45초

Arduino는 다른 위치에서도 경기 현황을 확인하는 용도입니다. Pi가 보내는 남은 시간과 통과·탈락 인원을 Bluetooth로 받아 LCD에 보여줍니다.

데이터가 나눠 들어오면 한 명령이 끝까지 들어온 뒤 처리합니다. 잘못된 값은 화면에 반영하지 않고, 정상적으로 표시하면 Pi에 알려줍니다.

LCD는 내용을 새로 쓸 때 남는 칸을 공백으로 채웁니다. 이렇게 이전에 표시했던 글자가 남지 않도록 했습니다.

이어서 경기 구역과 참가자를 정하는 방법은 홍성록님이 설명드리겠습니다.

[박정환 → 홍성록 인계]

## 5장 — 경기할 공간을 지정하고 시작할 때 들어온 사람을 참가자로 정합니다 / 홍성록 / 55초

네, 먼저 어디에서 누구와 경기할지 정하도록 했습니다.

웹 화면에서 경기할 공간의 가장자리를 클릭하면 구역을 만들 수 있습니다. 결승선의 양 끝과, 선을 넘어 도착할 쪽도 직접 지정합니다. 설치한 장소와 카메라 위치에 맞춰 설정하는 방식입니다.

그다음 시작 버튼을 누르면, 구역 안에서 카메라가 찾아낸 사람들을 이번 경기 참가자로 등록합니다. 나중에 들어온 사람은 자동으로 추가하지 않습니다.

[잠깐 멈춤 — 시작할 때 참가자를 정한다는 점을 전달]

등록한 참가자가 움직여도 되는 동안, 정해둔 방향으로 결승선을 넘으면 통과로 처리합니다.

그럼 멈춰야 할 때 움직인 사람은 어떻게 알아냈는지 설명드리겠습니다.

## 6장 — 기준 자세와 관절 위치를 비교해 제자리에서의 움직임도 확인합니다 / 홍성록 / 45초

움직임은 손목이나 어깨 같은 관절 위치를 비교해서 확인합니다.

멈춰야 하는 때가 시작되면 그때의 자세를 기준으로 잡습니다. 이후 관절 위치가 얼마나 달라졌는지 비교합니다. 사람이 화면에서 크게 보이거나 작게 보이는 차이도 계산에 반영했습니다.

다만 카메라가 잡는 관절 위치는 사람이 가만히 있어도 조금씩 흔들릴 수 있습니다. 그래서 짧은 시간 동안 여러 프레임에서 변화가 지속되는지 확인합니다.

몸이 잘 보이지 않아 비교하기 어려울 때는 판단을 보류합니다.

## 7장 — 인형 회전과 판정 시작을 확인한 뒤 움직임 결과를 반영합니다 / 홍성록 / 55초

이제 움직임을 언제부터 확인할지 맞춰야 합니다. 저희는 인형 회전 처리와 움직임 판정 시작을 다음 순서로 연결했습니다.

구호 재생이 끝나면 Pi가 인형을 앞으로 돌리라고 요청합니다. STM32가 회전 처리가 끝났다고 알려주면, Pi가 Jetson에 움직임 판정을 시작하도록 요청합니다. Jetson에서 시작됐다는 답도 받습니다.

그 뒤 Jetson이 ‘몇 번 참가자가 움직였다’고 알려오면, Pi는 현재 경기에서 나온 정보인지 확인합니다. 지금이 멈춰야 하는 때인지, 등록된 참가자인지도 확인한 뒤 탈락을 확정합니다.

같은 정보가 여러 번 들어와도 이미 정한 결과는 바뀌지 않도록 했습니다.

여기까지가 게임의 동작입니다. 개발 과정에서 개선한 세 가지는 박정환님이 설명드리겠습니다.

[홍성록 → 박정환 인계. 다음 슬라이드로 전환]

## 8장 — 역할을 정리하고 판정·처리 방식을 바꿔 통합 과정의 문제를 개선했습니다 / 박정환 / 135초

### 01 · 시간·상태 처리 / 약 60초

첫 번째는 시간과 게임 상태를 어디서 정할지였습니다.

처음에는 각 보드가 따로 처리하는 방향으로 생각했습니다. 하지만 같은 경기인데 LCD마다 시간이 다르게 보이면 안 됩니다. 인형이 움직이는 때와 판정하는 때도 맞아야 합니다.

그래서 남은 시간과 움직여도 되는 때, 통과·탈락 결과는 Pi 한곳에서 정하도록 바꿨습니다.

Arduino는 시간을 직접 줄이지 않고 Pi가 보내는 값을 표시합니다. STM32는 인형을 돌리고, 처리가 끝났다고 Pi에 알려줍니다.

이렇게 게임 진행은 Pi가 정하고, 각 보드는 동작과 표시를 맡도록 역할을 나눴습니다.

[오른쪽 방향키 한 번 — 2번 강조. 발표자 유지]

### 02 · 팔 움직임 누락 / 약 30초

두 번째는 제자리에서 팔을 움직여도 놓치는 문제였습니다.

처음에는 사람을 둘러싼 사각형의 중심이 얼마나 이동했는지 봤습니다. 그런데 그림처럼 팔만 움직이면 박스 중심의 변화는 작을 수 있었습니다.

그래서 앞서 설명한 고정 기준 자세와 관절 위치를 비교하는 방식으로 바꿨습니다. 놓친 장면은 다시 살펴보면서 작은 동작을 잡는 기준도 조정했습니다.

[오른쪽 방향키 한 번 — 3번 강조. 발표자 유지]

### 03 · 처리 지연 / 약 45초

세 번째는 처리 지연입니다. 사람이 지금 움직였는데 프로그램이 지난 화면을 보고 있다면, 그만큼 반응이 늦어집니다.

그래서 영상 수신, AI 분석, 화면 표시 과정에 걸리는 시간을 나눠 살펴봤습니다.

AI 계산에는 TensorRT FP16을 적용했습니다. 분석이 밀리면 가장 최근 프레임을 가져오도록 했고, 웹 미리보기도 따로 정한 간격으로 보여줍니다.

별도의 사람 검출 모델 비교에서는 PyTorch FP32의 12.76FPS에서 TensorRT FP16의 18.53FPS로, 처리량이 약 1.45배 늘었습니다. 화면 표시, 저장, Pi 통신을 제외한 결과이며, 현재 관절 게임 전체 성능을 뜻하는 수치는 아닙니다.

이어서 현황 공유와 결과 기록은 홍성록님이 설명드리겠습니다.

[박정환 → 홍성록 인계. 오른쪽 방향키로 9장 전환]

## 9장 — 같은 경기의 현황을 함께 보고 참가자별 결과를 기록으로 남깁니다 / 홍성록 / 40초

이렇게 진행한 경기는 LCD와 웹에서 확인할 수 있습니다.

경기는 기본 3분입니다. Pi가 남은 시간을 계산하고, 통과하거나 탈락한 사람 수가 바뀌면 두 LCD에 알려줍니다. 현장과 떨어진 곳에서 같은 경기의 진행 상황을 볼 수 있습니다.

웹에서는 남은 시간과 참가자별 결과를 확인합니다. 통과·탈락 같은 경기 기록은 데이터베이스에 저장하도록 했습니다.

버튼으로 시작한 경기가 인형 동작과 움직임 판단을 거쳐, 화면 표시와 결과 저장까지 이어지도록 구성했습니다.

## 11장 — 체험형 IoT 서비스로 / 홍성록 / 35초

재미와 실무 활용 가능성을 함께 갖춘 IoT 서비스를 고민하며, 놀이공원의 체험형 놀이시설을 떠올렸습니다.

이번에는 익숙한 놀이를 여러 장치가 함께 동작하는 게임으로 구현했습니다.

앞으로 참가자 인식과 결과 기록을 활용해 체험시설의 진행과 운영을 돕는 서비스로 발전시키고 싶습니다. 감사합니다.
